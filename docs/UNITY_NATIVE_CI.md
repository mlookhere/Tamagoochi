# Unity-native validation gate — Issue #33

This is a **separate prerequisite** of Unity migration Issue #31 / draft PR #32, not a replacement for the existing five GitHub repository checks. The workflow is **manual-only while activation, mobile modules and approval are unverified**. A skipped/absent native run is **not** native acceptance.

## Setup and security

1. Have an authorized maintainer configure a GitHub environment named `unity-native` with required reviewer approval and access restricted to trusted branches. Store `UNITY_EMAIL` and `UNITY_PASSWORD` plus **exactly one** of `UNITY_LICENSE` (Personal license file) or `UNITY_SERIAL` (Pro serial) as protected **environment secrets**; never commit them or echo their values. The guard rejects absent or ambiguous license modes before invoking GameCI. A license-server workflow requires a separate reviewed change.
2. Use **GitHub-hosted** runners, pinned GameCI v4 Actions and Unity `6000.0.62f1`; do not execute public-fork PR code with secret-enabled self-hosted runners. The workflow rejects unrelated refs and missing activation.
3. This manual workflow must exist on the repository **default branch (`main`)** to be dispatchable. After its reviewed integration, dispatch from `main` or `dev` with the `migration_sha` input set to the **current reviewed 40-character SHA** of `work/31-unity6-migration`. The workflow checks out precisely that commit and verifies it still equals the migration branch HEAD before exposing Unity activation to build/test actions, **then rechecks the HEAD after native tests and build**. Any intervening branch movement fails the workflow instead of approving stale results. A successful run records `migration_sha`, `workflow_sha`, `run_id`, and SHA-256 digests of the validated NUnit XML and Android APK in `unity-native-provenance.txt` beside the test/build evidence. The hashes bind the reported success to the preserved files; they do not independently prove native execution, signing, or device behavior. The workflow's source lives on the dispatch branch; its content checkout uses the reviewed migration revision. Missing/pending runs remain unresolved, not green.
4. The Unity source is checked out at the requested reviewed migration SHA, but the **verifier itself is separately checked out from `github.workflow_sha` into `.unity-ci-control/`**. Never run the verifier from the unmerged Unity branch (it does not contain the new CI script). After the Unity Editor build and test runner execute, the workflow verifies the separately checked-out trusted verifier's Git HEAD still equals `github.workflow_sha` and its entire checkout has no modified, untracked or ignored files before executing the validator. This also blocks newly introduced Python import-shadowing modules; Unity source is not permitted to replace or extend the evidence gate. The GameCI test runner also pins its CLI release to `v0.1.72`, rather than using a mutable `latest`. The Android build method creates and validates the Home scene, runtime panel/theme and 11 original sprite imports. The subsequent GameCI test runner executes NUnit EditMode in Unity. `ci/verify_unity_native.py` requires a real nonempty fully-passing NUnit3 XML with individually passing test-case entries matching the root counters, **at least 73 executed test cases (the source-audited baseline: 62 [Test] plus 11 [TestCase] invocations)**, and every authored direct-test method and original-art parameterized case from the six Unity source files. The verifier derives expectations from the exact checked-out Unity source and raises the minimum automatically when audited direct tests or sprite cases expand; unsupported `[UnityTest]`, `[Theory]`, `[TestCaseSource]`, and alternative NUnit parameter generators fail closed until the exact authored test discovery is reviewed and supported; reducing the audited 73-case floor still fails closed and a nonempty APK with a compiled binary AndroidManifest.xml whose declared chunk length matches the file and a DEX header with a three-digit ASCII version marker, null terminator, and matching declared bytecode file length. The APK must have unique ZIP member paths; duplicate manifest, DEX or Unity resource names are rejected as ambiguous. Unity ELF signatures are read without loading the full engine libraries into verifier memory. The APK also must include a Unity engine ELF library under `lib/*/libunity.so` and nonempty packaged player data under `assets/bin/Data/`, rejecting generic Android packages that lack Unity runtime contents. These are necessary sanity checks, not proof of authenticity, package signing, installation or execution.
5. Before accepting test results, the workflow checks `git diff HEAD` for the complete authored EditMode test directory and pinned Unity Editor version, and rejects any untracked EditMode source files. If the Editor or any build process mutates the reviewed fixture inputs, the evidence is invalid even when the checked-out commit SHA is unchanged. Generated scene, panel and other runtime assets may still be created by the legitimate editor build method.
6. GameCI's optional test-results check publisher is disabled with `githubToken: ''`, preserving the workflow's read-only GitHub permissions; actual NUnit and APK evidence is validated in the explicit fail-closed step. The validator's stdlib synthetic self-tests run in **Fast deterministic gates**. They prove only validation logic, **not** a native Unity run.

## Review both native artifact bundles together

After **separately authorized, successful** Android and unsigned iOS workflow runs, download/extract each Actions artifact into separate directories and run:

```bash
python3 ci/verify_unity_mobile_evidence.py \
  --android ./android-artifact \
  --ios ./ios-artifact \
  --migration-sha <reviewed-40-character-migration-SHA> \
  --workflow-sha <trusted-40-character-native-workflow-SHA>
```

The stdlib verifier requires **both** Android and iOS bundles to match the independently reviewed migration **and trusted workflow** commit SHAs. It rejects mismatched source commits, unreviewed workflow commits, reused run IDs, missing or duplicated Android NUnit reports, altered APK/XML contents, missing iOS launcher/UnityFramework binaries, unsafe binary paths, missing/failed Xcode build logs, mismatched recorded Xcode compiler versions, or iOS executable digests missing from their run's provenance. It intentionally requires the iOS run result to be `unsigned_xcode_compile_only`. Its fourteen synthetic regressions are included alongside the existing native verifier tests in the required PR fast gate via the `test_unity_*.py` discovery pattern. They do **not** run Unity or replace signed iOS/device QA. Keep source GitHub run URLs and artifact IDs in the human release record; the local verifier cannot independently attest GitHub artifact authenticity or approval. Neither absent native artifacts nor a passing repository CI run constitutes success.

## Not yet satisfied

- This workflow has not run a Unity Editor, and GameCI activation / builder path behavior is not yet proven. No editor, NUnit, or Android artifacts are approved.
- The separate `.github/workflows/unity-ios-native.yml` is **manual-only and unexecuted**. It requires an independently approved `unity-ios-native` environment on a trusted `main`/`dev` dispatch, with protected `UNITY_EMAIL`, `UNITY_PASSWORD` and exactly one of `UNITY_LICENSE` or `UNITY_SERIAL`. The workflow must first be reviewed into the default branch to be dispatchable. It checks out the current reviewed `work/31-unity6-migration` SHA, uses a GitHub-hosted `macos-15` runner and pinned Unity `6000.0.62f1` via GameCI to call `HomeSceneSetup.BuildIOSDevelopment`, requires a generated `Unity-iPhone.xcodeproj`, then runs `xcodebuild` for a generic iOS device with `CODE_SIGNING_ALLOWED=NO`. It fails if the Xcode project, compiled Mach-O launcher, or compiled UnityFramework binary is absent, requires arm64 slices in both binaries, records exact Xcode version, SHA-256 hashes of both binaries and reviewed source provenance, and retains generated Xcode sources, Xcode build logs and the compiled unsigned device products from `unity/Builds/iOS-derived/Build/Products/Release-iphoneos/` as Actions artifacts on failure or success when present. The build/runner behavior is not verified until a real authorized run.
- **Unsigned Xcode compilation is not mobile acceptance.** An iOS Xcode export is not itself a binary. The manual iOS job does not sign, notarize, install, launch or test a device build; provisioning, code signing with authorized Apple developer credentials, install/run on physical devices, accessibility/FPS/battery/art acceptance and branch-protected required checks remain distinct mandatory acceptance evidence. Android success never substitutes for iOS.
- After real authorized activation and successful same-head native runs, review a follow-up change enabling mandatory automatic native checks for Unity-changing PRs and configure branch protection. Do not treat manual-only, skipped, missing or older-SHA results as passing native gates.
- Keep Unity migration PR #32 draft until both mobile platform builds and actual device/accessibility/performance/art acceptance are evidenced.
