# Tamagoochi: isolated stylized 3D asset kit

**Prototype only. Not finished hand-modeled production art.** Issue #35. The existing Unity migration, gameplay, 2D art and CI remain untouched.

## Generate in Unity 6

1. Open the repository Unity project in editor 6000.0.62f1 after the project from draft PR #32 is available.
2. Select Tamagoochi > Art > Generate Stylized 3D Starter Kit.
3. Select Tamagoochi > Art > Audit Starter Kit and resolve any missing assets, exceptions or pink shaders.
4. Inspect Assets/TamagoochiArt/Generated/: Materials, Prefabs, Animations, Audio and CreatureCatalog.asset.
5. Instantiate the prefabs in a temporary test scene. CreatureMotion offers Pet, Feed, Play, Sleep, Wake, Startle and React methods.

## Asset architecture

- Runtime/: independent creature identity, prefab catalog and procedural motion; does not touch gameplay scripts.
- Editor/: deterministic Unity Editor creation of prototype meshes, materials, clips, VFX, nursery, audio and catalog.
- Manifest/: inventory and outstanding production requirements.
- Generated/: produced by the menu only after an actual Unity Editor run; must retain generated meta GUIDs in future revisions.

### Style direction

Original small plush-like fantasy animals, not exact real animals or copies of existing game creatures. Oversized friendly eyes, distinctive petal/fin/leaf appendages and warm pastel materials. Evolutions keep identifiable family anatomy while growing into entirely new forms.

### Important animation limitation

The .anim clips currently animate VisualRoot positions and scales as reusable movement **blockouts**. CreatureMotion also writes these transforms. Disable CreatureMotion when an Animator drives those same transforms, or move authored animation to separate bones, to avoid conflicts. There is no gameplay integration or Animator controller in this asset-only PR.

### Production pipeline after prototype

1. Approve orthographic concept turnarounds and evolution silhouettes.
2. Author source meshes in Blender or equivalent, clean UVs, skin weights, and facial blend shapes; export FBX/glTF.
3. Use modular shared skeleton conventions and accessory/appendage bones where compatible.
4. Animate all 16 behavior states with complete facial acting and transitions, including reduced-motion alternatives.
5. Optimize materials, atlas textures, LODs and particle counts for low/mid-range mobile.
6. Produce hand-authored toys, furniture, environment sets, custom particle sprites, Foley and UI thumbnails.
7. Keep stable creature IDs when swapping visual prefabs so gameplay integration can happen separately.

### Production gates

These are goals, not measured results: aim for under 20k triangles per baby creature, constrained materials and draw calls, legible expressions at small screen scale, and safe non-strobing VFX. Native Unity import/compile, test-run, Android/iOS builds and device performance have **not been verified**. Existing repository CI must not be counted as Unity evidence.

The concept art shown in the conversation is a **visual reference**, not a UV-unwrapped skinned mesh. Generated meshes use Unity primitives and cannot match the visual finish of the concept renders without further model creation.

Review the asset-manifest.json and PRODUCTION_BACKLOG.md before marking an asset production-ready.
