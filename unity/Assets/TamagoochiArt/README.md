# Tamagoochi: isolated stylized 3D asset kit

**Prototype only. Not finished hand-modeled production art.** Issue #35. The existing Unity migration, gameplay, 2D art and CI remain untouched.

## Generate in Unity 6

1. Open the repository Unity project in editor 6000.0.62f1 after the project from draft PR #32 is available.
2. Select Tamagoochi > Art > Generate Stylized 3D Starter Kit.
3. Select Tamagoochi > Art > Audit Starter Kit and resolve any missing assets, exceptions or pink shaders.
4. Inspect Assets/TamagoochiArt/Generated/: Materials, Prefabs, Animations, Audio and CreatureCatalog.asset.
5. Instantiate the prefabs in a temporary test scene. CreatureMotion offers Pet, Feed, Play, Sleep, Wake, Startle and React methods.

## Asset architecture

- Runtime/: independent creature identity, prefab catalog and procedural motion; does not touch gameplay scripts.
- Editor/: deterministic Unity Editor creation of prototype meshes, materials, clips, VFX, nursery, audio and catalog.
- Manifest/: inventory and outstanding production requirements.
- Generated/: produced by the menu only after an actual Unity Editor run; must retain generated meta GUIDs in future revisions.

### Style direction

Original small plush-like fantasy animals, not exact real animals or copies of existing game creatures. Oversized friendly eyes, distinctive petal/fin/leaf appendages and warm pastel materials. Evolutions keep identifiable family anatomy while growing into entirely new forms.

### Important animation limitation

The .anim clips currently animate VisualRoot positions and scales as reusable movement **blockouts**. CreatureMotion also writes these transforms. Disable CreatureMotion when an Animator drives those same transforms, or move authored animation to separate bones, to avoid conflicts. There is no gameplay integration or Animator controller in this asset-only PR.

### Production pipeline after prototype

1. Approve orthographic concept turnarounds and evolution silhouettes.
2. Author source meshes in Blender or equivalent, clean UVs, skin weights, and facial blend shapes; export FBX/glTF.
3. Use modular shared skeleton conventions and accessory/appendage bones where compatible.
4. Animate all 16 behavior states with complete facial acting and transitions, including reduced-motion alternatives.
5. Optimize materials, atlas textures, LODs and particle counts for low/mid-range mobile.
6. Produce hand-authored toys, furniture, environment sets, custom particle sprites, Foley and UI thumbnails.
7. Keep stable creature IDs when swapping visual prefabs so gameplay integration can happen separately.

### Production gates

These are goals, not measured results: aim for under 20k triangles per baby creature, constrained materials and draw calls, legible expressions at small screen scale, and safe non-strobing VFX. Native Unity import/compile, test-run, Android/iOS builds and device performance have **not been verified**. Existing repository CI must not be counted as Unity evidence.

The concept art shown in the conversation is a **visual reference**, not a UV-unwrapped skinned mesh. Generated meshes use Unity primitives and cannot match the visual finish of the concept renders without further model creation.

Review the asset-manifest.json and PRODUCTION_BACKLOG.md before marking an asset production-ready.

## Sculpt, skeletal rig and facial performance studies (Issue #35 continuation)

The original low-detail generator remains unchanged. New tools add a separately named, replaceable *deformation-capable study* for Puffino:

1. Run **Tamagoochi > Art > Generate Sculpt-Ready Puffino Rig** to author five UV-mapped skinned mesh assets (48 x 32 parametric topology), 9 pose bones, four face blend shapes and a sculpt study prefab under `Generated/SculptReady/`.
2. The sculpt generator automatically creates six additional expression clips (happy, pouty, curious, eating, sleepy, blink) with Unity's `blendShape.*` animation bindings.
3. Use **Tamagoochi > Art > Audit Sculpt-Ready Puffino** and **Audit Facial Animation Clips**. The audit checks mesh/skin/blend-shape/clip identities; it is not a substitute for actual Editor render review.
4. Run **Tamagoochi > Art > Generate Evolution VFX Studies** and **Audit Evolution VFX Studies** for five finite-burst pastel effect prototypes: heart burst, dream drift, forest growth, lunar evolve and ember evolve.
5. Blender authoring source lives under `DCC/make_puffino_sculpt.py` and generates an editable `.blend` quad-mesh study plus an exported skinned/morph-target `.glb` *when run in Blender*. See `DCC/README.md`.

### Animation ownership

- `CreaturePerformance` synchronizes `CreatureMotion` with `CreatureFacialRig` and exposes pet/feed/play/sleep/wake interaction and reduced-motion control.
- Live procedural face/bone motion and baked Animator animation must not write the same bones or blend shapes simultaneously. Disable the relevant procedural component when previewing authored clips, or use additive animation on a separate rig layer.
- Rig hierarchy and shape-key naming contracts are in `Manifest/ART_PIPELINE.md`; preserve bone names and exposed shape keys across replacement meshes.
- These studies increase geometric and animation fidelity *infrastructure*, but are not finished organic sculpts or professional effects. Blender and Unity imports/exports still require real tooling and validation.

### Acceptance remains explicit

Static source coverage and repository CI are not proof of Unity C# compilation, prefab generation, actual Blender execution, skinned deformation, or mobile performance. Record each real native/visual result in Issue #35 before claiming that stage complete.

## High-detail visual quality gate

The Blender sculpt source has an organic geometry pass (`DCC/sculpt_details.py`): tapered quad ear-fins, cheek/forelock tufts, eye and iris layers, freckles, toe pads, and four recognizable original species silhouettes. It also creates portable UV albedo PNGs for fur, fins and tail markings so they can survive GLB export.

Before an asset may be called high-detail/game-ready:

1. Generate both `--profile sculpt` and `--profile mobile` files for each species in Blender. The Blender script now requires `validate_glb.py` to confirm actual skinned geometry, facial blend shapes, UVs, texture exports and mobile triangle budgets.
2. Generate the 32 native Blender proof images using `DCC/render_quality_review.py` (4 views, 3 facial expressions and one real mobile-profile phone capture per starter).
3. Visually compare every image and an animated gesture preview against the approved concept art; score shape, expression, distinct anatomy, materials, deformation and game-camera readability as defined in `DCC/VISUAL_QUALITY_GATE.md`.
4. Validate imports and actual skinned animation in the Unity Editor, then verify the target phones. **The existing repository CI is not this visual gate.**

Neither Blender nor the licensed Unity Editor is installed here. Therefore these sources are committed, but **no real model render, generated GLB or aesthetic approval can honestly be reported yet**. PR #36 remains draft. Do not substitute concept images for imported game asset screenshots.

## Native FBX import gate (Unity 6)

The Blender renderer produces both sculpt and mobile FBX files for every starter. Download the actual reviewed workflow artifact and copy its eight `models/<species>_<profile>.fbx` files into `Assets/TamagoochiArt/Imported/` inside the combined Unity project. Keep the artifact's source revision and checksum in the review record; do not use untrusted models.

In Unity 6000.0.62f1, let ModelImporter process those files and select **Tamagoochi > Art > Audit Imported FBX Creatures**. For headless validation after preparing the imported assets, execute the same public method using `-batchmode -quit -executeMethod Tamagoochi.Art.Editor.ImportedCreatureAudit.Audit`.

The audit fails closed unless all eight real Unity-imported models contain skinned meshes, valid bind poses and bones, UVs, exactly one head with Smile/Pout/CheekPuff/Curious blend shapes, valid triangular submeshes and a mobile geometry count at or below 30,000 triangles. Passing the Blender re-import does **not** replace this Unity Editor audit.

After the Editor audit succeeds, use **Tamagoochi > Art > Generate Imported Creature Previews** (or `-executeMethod Tamagoochi.Art.Editor.ImportedCreatureAudit.GeneratePreviews`) to build four independent, replaceable mobile-model preview prefabs and `ImportedCreatureCatalog.asset` under `Assets/TamagoochiArt/Generated/Imported/`. These prefabs keep the existing species IDs and do not overwrite the primitive prototype catalog, gameplay, or production scenes. Run the Unity native audit and visually inspect the generated prefabs before gameplay integration; generating them does not constitute art approval. Real Unity Editor compilation, animation, materials, axis/scale, Android/iOS builds and on-device creative/performance testing are separately required.
